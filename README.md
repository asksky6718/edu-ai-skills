# 能工巧匠 · 职业教育 AI 技能包合集

> **出品**：海南能工巧匠职业教育有限公司（下称「能工巧匠」）
> **定位**：能工巧匠「**格物圈**」智能体能力供给网络面向公众开放的**能力层样本库**
> **落地**：技能包全部来自真实交付项目，经格物圈发布给用户，并直接落到具体项目上

面向职业教育场景的 AI 技能包（Agent Skills）合集：把职教行业里**高频、重复、容易踩坑**的专业流程，锻造成 AI 智能体可直接调用的技能包。

---

## 这个合集在能工巧匠体系里的位置

能工巧匠是一家「**1 位决策者 ＋ 5 个智能体**」运营的职业教育公司。它不是纯研发公司——**研发是手段，交付与收入是目的**。公司唯一的战略项目是 **格物圈**：一套把智能体能力**供给**给行业的能力网络（行业赋能的 FDE 引擎）。

本仓库是这个网络**公开出来的能力层**，三层关系如下：

```
能工巧匠（母品牌 · 对外主体）
   └─ 格物圈（战略项目 · 智能体能力供给网络）
         └─ 技能包合集（本仓库）  ＝ 供给网络公开的能力层
               └─ 具体项目落地    ＝ 职称评审 / 培训机构资质 / 人工智能训练师培训 / …
```

## 合集的意义

1. **供给侧**：职教行业里真正稀缺的不是资料，是**把资料变成可执行动作**的能力。这里收录的每个技能包，都是一条被跑通过的**完整动作链**（谁做 → 做什么 → 交什么 → 过不了怎么办）。
2. **落地侧**：技能包不是演示品。每个都对应能工巧匠在交付的真实业务，**由格物圈发布给用户、被具体项目直接调用**；仓库里的版本即为项目上线所用版本。
3. **方法侧**：合集公开的不只是成品，还有**生产方法**——目录怎么排、根路由怎么写、子技能该放什么、发布前过哪几道闸门。方法一致，才能保证「换人、换模型、换软件」之后能力不丢失。
4. **护栏侧**：职教业务涉及资质、政策、对外承诺，容错极低。每个技能包都把**红线**写成硬约束：政策口径回官方原文核、不可逆动作必须人到场、面向中小学生的校外培训不代做。

## 收录标准

一个流程要能进这个合集，必须同时满足四条：

1. **有真实业务承载**——不是凭空想出来的场景，是正在交付、能被验收的项目流程；
2. **动作链完整**——进门条件、本步动作、出门交付物、责任方、失败处置，五问都有答案；
3. **可机械化的先机械化**——能用脚本核的（表格核对、清单打勾、口径比对）一律给脚本，**机器认不出来就拒答，绝不把「没认出来」当成「全都没有」**；
4. **护栏写死**——不可逆动作、涉及钱/章/签字/到场/对外承诺的，一律标注必须人工完成。

## zhicheng-pm 详解

**一句话**：职称申报的坑不在填表，在一路的岔口。这个技能把它拆成**五道门**——能机器干的先干完，该人上手的提前备好、一次交接清。

**五道门（顺序推进，不可跳过）**

```
第 1 道 · 资格      理工类·年限·入口条件，不过就停
   ↓
第 2 道 · 定评委会   按单位归口加岗位方向，机器推荐、人拍板
   ↓
第 3 道 · 锁政策     当年通知原文照抄学时·论文·窗口·费用
   ↓
第 4 道 · 补缺口     学时·业绩·论文·单位盖章，逐项消
   ↓
第 5 道 · 申报执行   扫码·提交·缴费·纸质·答辩 —— 必须本人在场
```

**两层结构**：下层先把**一个人**从资格门打到拿证（地基）；上层才是**一批人**的进度台账（汇总）。
**批量不是第 6 道门**，而是把单人主线跑 N 遍后的一次汇总——单人层跑不通，台账就是空的。

**机器全包 9 项**：政策检索 · 资格判定 · 评委会推荐 · 学时计算 · 业绩改写 · 论文提纲 · 材料核对 · 时间排期 · 逐栏填写手册。

**必须本人 7 项**：随申办扫码登录 · 点「提交」 · 缴费转账 · 单位盖章 · 本人签字 · 纸质材料报送 · 答辩出场。
（判断标准：这动作做错了能不能撤销？不能撤销，或涉及钱、章、签字、本人到场 → 必须人做。）

**九条硬红线**：政策必回原文核 · 不锁评委会不作业 · 理工类是硬门槛 · 资历截止日分上下半年 · 实名与联系方式不进共享库 · 不宣称代办 · 不可逆动作须人工确认 · 不代签代编 · **顺序不可跳**。

装法与用法详见 [skills/zhicheng-pm/README.md](skills/zhicheng-pm/README.md)，版本变更见 [CHANGELOG.md](skills/zhicheng-pm/CHANGELOG.md)。

## vocational-training-school-setup 详解

**一句话**：办培训学校的坑不在填表，在**资质是有先后顺序的**——先有培训资质才能招生，先有法人登记才能开课，「能办学」不等于「能发证」。这个技能**一门一门带你走**：先判你该走哪条路，再一门给一张卡（进门要什么·本门做什么·出门交什么·谁动手·过不了怎么办）。

**第 0 步 · 先判路（三问）**

```
1. 已有办学许可证？   没有 → 走主线 A（从零新办，八门）
                      有   → 看第 2 问
2. 要对外发职业技能等级证书？ 要 → 主线 A 走完再走 C（评价资质备案）
3. 面向中小学生？     是 → 停手：那是教育/体育·校外培训，不是人社体系，本技能不代做
```

**两条主线**

```
主线 A · 从零新办一家培训机构（八门）
  A1 立项与路线 → A2 名称核准 → A3 筹设 → A4 正式设立
  → A5 审查许可 → A6 法人登记 → A7 开办配套 → A8 依法运行

主线 B · 已有机构新设职业（工种）（五门）
  B1 主体与许可范围 → B2 定职业等级＋门槛表 → B3 组申报包（六大类）
  → B4 报送与审查 → B5 获批纳管

主线 C · 评价资质（社评组织备案，须点名才做）
```

**六条能力**

```
手把手主线   先判路，再一门一门出五问卡（run-through）
   ↓
口径与路线   锁属地口径（审批机关·依据文号·材料来源）＋定资质路线
   ↓
推进表核对   跑脚本机械核对：资质链·日期·状态·空值·顺序倒置
   ↓
交付物清单   逐项打勾＋标证据位置＋常见退回原因
   ↓
运行合规     年检·培训台账·培训协议·收费公示·变更与终止
   ↓
评价资质     社评组织遴选备案（须点名）
```

**三条铁律**：

1. **以属地当期公开文件为准** —— 培训类审批按区/县级人社部门执行，同一省内不同县市的面积门槛、资金门槛、办结时限都可能不同。技能里收录的湖北、上海两份口径**只作对照与提问用**。
2. **两种资质别混为一谈** —— **办学许可**（能面向社会办培训）≠ **社评组织备案**（能面向社会做职业技能等级认定、发职业技能等级证书）。
3. **两条通道别混** —— **人社·职业技能培训** ≠ **教育/体育·校外培训**（托管、体育、艺术、学科类）。审批机关、材料、门槛完全不同；出现「中小学生」即停手，不代做、不混装。

**机器全包**：属地口径检索与对照 · 推进表机械核对 · 交付物逐项打勾 · 缺口与催补清单 · 年检与台账排期 · 申报包结构配方。

**必须人到场**：取属地当期原件 · 实名申报 · 场所与消防核实 · 验资 · 教师劳动合同 · 单位盖章 · 签字 · 提交 · 缴费 · 现场配合 · 领证。

**配套参考件**：湖北 / 上海两份官方口径 · 九段全流程细目（条件·材料·时限·坑） · **执行主线**（A 八门／B 五门，每门五问卡） · **人工把关点**（11 项机器不代办） · **两条通道对照** · 交付物检查表与常见缺口 · **职业（工种）申报包配方**（六大类、逐份要点、门槛表） · **脱敏案例**（一套实际报送的申报材料实录）。

装法与用法详见 [skills/vocational-training-school-setup/README.md](skills/vocational-training-school-setup/README.md)，版本变更见 [CHANGELOG.md](skills/vocational-training-school-setup/CHANGELOG.md)。

## OPC 五部门经营工具包 详解

**一句话**：把一家教育类培训机构的**五个部门**各锻造成一个技能包，部门之间用机器可核的交接件串成一条流水线——每道交接过「门」校验，能机器干的全交给机器，涉钱、涉对外、涉实名的一律挂起等人。

```
鱼塘模型（招生 → 成交 → 生产 → 交付 → 复购）
  opc-market      获客：智能体量产内容、触点收敛成线索 lead.json（L1–L9 级别标签）
     ↓
  opc-sales       成交：lead + course → 订单 order.json（审批留痕三件，缺一即拒）
     ↓
  opc-product     生产：按目标级别产课程 course.json（大纲有出处、考试绑题库）
     ↓
  opc-service     交付：order + course → 交付记录 delivery.json（课堂有声非空壳）
     ↓
  opc-aftersales  复购：delivery + 计量 + 审计 → renewal.json
                  复购信号 next_level_course ──回流 opc-market（鱼再入塘）
```

**五个部门的共同纪律**：

1. **交接件即合同**——上游产物字段不齐直接拒收，绝不「先收下再补」；
2. **门内机判、门外人判**——能用脚本核的（齐备性／格式／留痕）一律脚本；价格、承诺、付款、盖章、实名账号一律人做；
3. **级别共用一把尺子**——招生分级（L1–L9）与学员能力分级同标尺，获客、排课、交付、晋级四处口径不打架；
4. **复购闭环**——售后判定的晋级信号自动回流市场部，形成「打鱼再放苗」。

装法与用法详见各包 [skills/opc-market/README.md](skills/opc-market/)（其余四包同目录），版本变更见各包 CHANGELOG.md。

## 安装

```bash
# 把技能目录复制到你的技能目录（ opc 五包同理：cp -r skills/<技能名> <技能目录>/ ）
cp -r skills/zhicheng-pm ~/.workbuddy/skills/                        # WorkBuddy
cp -r skills/vocational-training-school-setup ~/.workbuddy/skills/    # WorkBuddy
cp -r skills/opc-market ~/.workbuddy/skills/                          # WorkBuddy

cp -r skills/zhicheng-pm ~/.codex/skills/                            # Codex 系
cp -r skills/vocational-training-school-setup ~/.codex/skills/        # Codex 系
cp -r skills/opc-market ~/.codex/skills/                              # Codex 系
```

- 每个技能包遵循 Agent Skill 规范（frontmatter：`name` / `description`），根文件只做路由，业务正文下沉到子技能与 `references/`
